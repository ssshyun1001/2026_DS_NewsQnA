## 2026-11-16 — DB 이전, Hybrid 검색, Cloud Run 배포, 여러 사용자, 웹 디자인

### DB: Supabase(PostgreSQL + pgvector) → Google Cloud Firestore (`27fb996`)

- **왜**: 웹이 가끔 DB를 못 불러옴. Supabase가 싱가포르(`ap-southeast-1`)라 서울 Cloud Run과 멀고(연결 약 1.4초 · 왕복 약 80ms), 세션 풀러 동시 연결 한도(약 15)에 걸릴 수 있었음
- **위치**: Firestore `(default)`, 서울 `asia-northeast3`, Native · Standard. 동시 연결 한도 없음, 1주일 안 써도 안 멈춤
- **속도** (로컬 → 서울): 문서 읽기 약 66ms, 벡터 검색 약 0.1~0.2초
- **비용**: 무료 한도 하루 읽기 5만 · 쓰기 2만 · 저장 1GiB. 질문 1번 ≈ 읽기 100~250
- **코드**: `qupict/db.py`를 Firestore로 다시 씀 (함수 이름 · 인자 그대로). 흩어져 있던 SQL 조회(현황 · 남은 일 세기 · Top 5 · 실험용)도 `db.py` 함수로 모음. `schema.sql` · `docker-compose.yml` 삭제
- **벡터 검색**: `find_nearest`(코사인, 정확한 KNN). 청크의 `search_keys`("topic id:판정")와 발행일로 거른 뒤 찾음. 유사도 = 1 − 거리 (pgvector 값과 같음)
- **데이터 이전**: `tools/migrate_supabase_to_firestore.py`로 6,355건 (임베딩 · topic id 그대로). 14개 topic 모두 벡터 검색 결과가 예전과 같은 청크 · 같은 순서(유사도 차 0.0001 이하)
- **바뀐 값**: `image_id` 숫자 → 문자열(`"기사키/이미지키"`), `DATABASE_URL` → `FIRESTORE_PROJECT=qupict`, 실험 B 엔진 이름 `pgvector` → `db`
- **인증**: 조직 정책상 서비스 계정 키를 만들 수 없어 본인 Google 계정(`gcloud auth application-default login`)으로. Cloud Run은 서비스 계정에 `Cloud Datastore 사용자` 역할

| 방식 | 정제된 질문 Recall@5 | 정제된 질문 MRR | 다양한 형태 질문 Recall@5 | 다양한 형태 질문 MRR | 질문당 시간 |

- **검색 순서** (`retrieval.search_topic`)
  ```text
  질문 (검색어가 없으면 앞에 붙임: "근황은?" → "강남 근황은?")
    ① 벡터 검색   뜻이 비슷한 청크 (유사도 0.5 미만 버림)
    ② 키워드 검색 질문 단어(kiwi 형태소)가 많이 · 드물게 겹치는 청크 (BM25)
    ③ RRF        청크 점수 = Σ 1 / (60 + 순위)
    → 상위 5개 청크로 답변
  ```
- **파일**: `qupict/bm25.py` 새로 추가, `retrieval.py` 기본값 Hybrid, `db.py`에 `search_chunk_rows` · `count_search_chunks`, `web.py`는 준비 끝나면 `warm_up_search`로 키워드 인덱스를 미리 만듦, `exp_b_retrieval.py`에 `hybrid` 추가
- **확인** (방송인 강남 "강남이 괌에서 무슨 일을 했어?"): 벡터만 1개 → Hybrid 5개. 키워드 인덱스 처음 약 7초, 이후 질문 약 1.4초
- **알아 둘 점**
  - 키워드 인덱스는 topic마다 서버 메모리. 검색 대상 청크 수가 바뀌면 자동으로 다시 만듦. 실패하면 벡터 결과만으로 답함
  - 실험은 기사 단위로 합쳤고 서비스는 청크 단위로 합침. 키워드로만 찾은 청크는 유사도 기준(0.5)을 안 거침
  - 이어지는 질문은 검색에 이전 대화를 안 씀 (예전엔 HyDE가 봤음). 답변 LLM에는 그대로 들어감
  - kiwi가 "괌" 같은 짧은 지명을 명사로 못 잡을 때가 있음
  - 예전 방식: `search_topic(..., use_hybrid=False)`(벡터만), `use_hyde=True`

### 중복 제거: "하나만 넘어도" → "4개 중 2개 이상" (`5858103`)
